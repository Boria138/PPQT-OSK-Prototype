# System Keyboard

Экранная клавиатура Linux: **X11/XWayland** и **нативный layer-shell для niri**.
Ввод только через **uinput** во всех сеансах. Раскладка COSMIC читается через
нативный протокол Wayland, без libei и D-Bus. XTest, портал и GNOME-расширение не используются. Интерфейс Python / GTK 3.

## Окружение с uv

Нужны системные Python, PyGObject (`gi`) и GTK 3 с introspection.
PyGObject должен соответствовать именно системной версии Python:

```sh
uv venv --python /usr/bin/python3 --system-site-packages .venv-system
source .venv-system/bin/activate
python -c "import gi; gi.require_version('Gtk', '3.0'); from gi.repository import Gtk; print('GTK доступен')"
```

Если `.venv-system` уже существует и работает, повторно создавать её не нужно.
Запускайте из каталога проекта через `python -m system_keyboard`; установка
пакета не обязательна. Обычный `uv run` может выбрать другую `.venv`.

Зависимости ввода:
- X11-подписи: libX11 (только чтение XKB, не инъекция ввода);
- uinput: python-evdev (`evdev`) и доступ к `/dev/uinput`;
- layer-shell: gtk-layer-shell с introspection и поддержка протокола композитором;
- подписи: libxkbcommon и системная база xkeyboard-config.

Для uinput нужен загруженный модуль ядра и ограниченное разрешение администратора
на `/dev/uinput`. Проект не меняет права и не запускает sudo.
Не запускайте весь GUI от root и не используйте `chmod 666 /dev/uinput`.
Если evdev отсутствует: `uv pip install --python .venv-system/bin/python evdev`.

## Запуск

### GNOME Wayland и другие сеансы с обычным XWayland

```sh
python -m system_keyboard
```

Вне COSMIC/niri/Sway/Hyprland автоматически выбирается X11-интерфейс. `GDK_BACKEND=x11` больше не нужен:
программа задаёт backend GTK до его загрузки. Интерфейс можно указать явно:

```sh
python -m system_keyboard --ui x11
```

Окно без рамки, типа dock, шириной 1000 px (не больше рабочей области),
по центру у нижнего края основного монитора. Учитывается место, зарезервированное системными панелями
через X11 workarea, поэтому клавиатура располагается над нижней панелью.
Если панель не резервирует рабочую область (автоскрытие или «скрывать под окнами»),
общего API её границ нет. Специальных интеграций с DE нет; задайте дополнительный
отступ вручную, например для панели высотой 40 пикселей:

```sh
python -m system_keyboard --ui x11 --bottom-margin 40
```

Отступ сохраняется независимо от видимости панели и добавляется к рабочей области.
Он также доступен в layer-shell. При смене панели на «показывать всегда» обычно
достаточно стандартного отступа 0, иначе зарезервированное место будет учтено дважды.
Позиция пересчитывается при изменении размера окна/состава мониторов.
Не используется `override_redirect`: поведение dock и расположение поверх других
окон зависят от оконного менеджера/композитора. Пространство под X11-окно пока
не резервируется; оно может перекрывать нижнюю часть приложения.
На xwayland-satellite этот интерфейс не заявлен как надёжный: для niri используйте layer-shell.

### COSMIC: layer-shell + uinput

```sh
python -m system_keyboard
# Фиксированные подписи, например:
python -m system_keyboard --layout ru
```

При `XDG_CURRENT_DESKTOP=COSMIC` (в том числе в списке через двоеточие)
автоматически выбирается нативный Wayland layer-shell, без XWayland.
Нужны gtk-layer-shell и доступ к `/dev/uinput`, как и для других layer-shell-сеансов.
Окно не захватывает клавиатурный фокус; ввод остаётся через uinput.

При `--layout auto` карта XKB приходит через `wl_keyboard`, а активная группа —
через `zcosmic_keyboard_layout_manager_v1`, даже без клавиатурного фокуса.
Нужна системная библиотека `libwayland-client.so.0`; libei и D-Bus не используются.
Штатная COSMIC OSK может работать параллельно: её имя и соединения не затрагиваются.
Подписи следуют за внешним переключением раскладки, в том числе для вариантов XKB,
и обновляются каждые 150 мс. Caps Lock синхронизируется через LED-события,
которые композитор отправляет нашему uinput-устройству: без D-Bus/libei и без
доступа к физическим `/dev/input/event*`. XKB учитывает Caps Lock и Caps+Shift
при формировании подписей. Shift/AltGr учитываются для кнопок этой клавиатуры;
состояние удерживаемых Shift/AltGr физической клавиатуры без фокуса не читается.
Кнопка «Язык» отправляет заданное `--switch-shortcut`, а результат переключения
считывается из состояния COSMIC. Автопоказ по активации текстового поля не реализован.
Если протокол COSMIC недоступен при запуске, выводится предупреждение и
используются ручные подписи US/RU без синхронизации с внешними переключениями.
`--ui x11` по-прежнему доступен явно.

### niri, Sway и Hyprland: layer-shell + uinput

```sh
python -m system_keyboard
# или явно:
python -m system_keyboard --ui layer-shell --layout auto
```

Сеанс определяется по `NIRI_SOCKET`, `SWAYSOCK`,
`HYPRLAND_INSTANCE_SIGNATURE` или `XDG_CURRENT_DESKTOP`.
Окно компактное (1000 px), привязано только к нижнему краю и центрировано по горизонтали,
не запрашивает клавиатурный фокус и резервирует место через exclusive zone.
При отсутствии gtk-layer-shell программа выдаёт ошибку, без перехода на обычное
Wayland-окно. При `--layout auto` подписи обновляются каждые 150 мс через IPC:
`niri msg --json keyboard-layouts`, `swaymsg -t get_inputs -r` или
`hyprctl -j devices`. Соответствующая утилита должна быть в PATH.
Названия раскладок и вариантов сопоставляются с системным реестром XKB.
В Hyprland выбирается основная клавиатура; в Sway раскладки клавиатур должны
совпадать, иначе определение выдаёт ошибку. Физические Shift/Caps Lock через IPC
не отслеживаются.

В автоматическом режиме кнопка «Язык» в Sway и Hyprland переключает раскладку
через IPC (в Sway — всех клавиатур, в Hyprland — основной), а не через
`--switch-shortcut`. В niri используется заданное сочетание.
Если начальное определение недоступно, программа предупреждает в stderr и
переходит на ручные подписи US/RU. Они переключаются кнопкой «Язык» вместе с
отправкой системного сочетания, но не синхронизируются с внешними изменениями.
Для пользовательских раскладок вне реестра задайте `--layout ru` (или другой
язык) явно: это фиксированные подписи, системную раскладку выбирайте отдельно.

### Настоящий X11-сеанс

```sh
python -m system_keyboard
```

Ввод также идёт через uinput: доступ к `/dev/uinput` нужен и в X11.
Выбора backend'а больше нет, параметр `--backend` удалён.

## Язык и модификаторы

В X11-интерфейсе по умолчанию `--layout auto`: подписи читаются из текущей карты
XKB и обновляются каждые 150 мс. Учитываются группа, Shift, AltGr и Caps Lock.
Под Wayland это состояние XWayland; синхронизация с нативными приложениями
зависит от композитора. IBus/IME не моделируются.

Фиксированные подписи: `--layout ru`, `--layout de`, `--layout us --variant dvorak`.
Они не меняют системную раскладку и не следуют за её переключениями.
Доступные языки/варианты: `python -m system_keyboard.layouts --list`.
Геометрия клавиатуры пока одна компактная; автоповтора нет.

Кнопка **«Язык ⟳»** отправляет `KEY_KBD_LAYOUT_NEXT` через uinput.
Запасные сочетания, если композитор не обрабатывает служебную клавишу:

```sh
python -m system_keyboard --switch-shortcut super-space
# Также: alt-shift, ctrl-shift, next-layout
```

Служебная клавиша требует поддержки со стороны XKB/композитора и нескольких
настроенных раскладок. Это не универсальный обход настроек рабочего стола.
Shift/Ctrl/Alt/AltGr/Super фиксируются до следующей обычной клавиши.
Повторный клик отпускает модификатор, отдельная кнопка отпускает все.
При закрытии модификаторы отпускаются и backend закрывается.
Экран блокировки, вход в систему и TTY не поддерживаются.

## Проверки

```sh
python -m unittest discover -s tests -v
python -m compileall -q system_keyboard tests
```

X11-интеграционный тест запускается только с `SYSTEM_KEYBOARD_TEST_X11=1`
на отдельном тестовом X-сервере: он меняет его раскладку. Не включайте его на
рабочем дисплее. Остальные тесты не инъецируют события в ваш рабочий стол.

Ручная проверка: выбрать поле редактора, проверить буквы, Backspace, Enter,
Shift → буква, Ctrl → A, кнопку языка, сохранение фокуса и положение у нижнего
края. В Wayland отдельно проверить нативное приложение и XWayland-приложение.
Наличие тестов не доказывает совместимость конкретного композитора.

### GSettings

`python -m system_keyboard --layout gsettings` явно использует схему
`org.gnome.desktop.input-sources`: `sources` задаёт список XKB-источников
(включая варианты `us+dvorak`), первый элемент `mru-sources` — последний
интерактивно выбранный источник. Единственный источник используется и без истории.
Нужны PyGObject/Gio и установленная схема. Подписи обновляются по истории;
это не достоверное чтение активного источника Shell, о чём сообщает строка статуса.
Пустой список, неизвестная история, источники IBus и `per-window=true`
приводят к явной ошибке, а не угадыванию раскладки.

В современных схемах игнорируемый GNOME ключ `current` не используется.
Для старых схем с исходным английским описанием `current` без отметки
`DEPRECATED` сохранено чтение индекса; при неизвестном описании применяется
консервативный режим истории. GSettings не предоставляет команды переключения:
кнопка языка читает список `org.gnome.desktop.wm.keybindings switch-input-source`
при каждом нажатии и отправляет первое доступное сочетание. Поддерживаются
Ctrl, Alt, Shift, Super и клавиши, разрешаемые через GDK; неподдерживаемые
варианты пропускаются, отсутствие подходящих вызывает ошибку.
Явный `--switch-shortcut` позволяет переопределить сочетание.
Запись в `mru-sources` не выполняется: она не переключает раскладку Shell.
KDE не синхронизирует свои раскладки с этими настройками.
В режиме `--layout auto` адаптер выбирается для GNOME по
`XDG_CURRENT_DESKTOP` (включая `ubuntu:GNOME`). В остальных окружениях
автоматический выбор остаётся прежним.
